# `backend/.env.example`

> Added in **patch 01** · [View the file](../../../backend/.env.example)

## What it is for

A **template** for your personal `backend/.env` file. Settings that differ between
computers (ports, passwords, secret keys) live in `.env`, not in the code.

```bash
cp .env.example .env     # make your own copy, then edit it
```

- `.env.example` **is** committed: it shows which settings exist, with safe example values.
- `.env` is **not** committed (see `.gitignore`), because it will hold real secrets
  from patch 02 on.

## The settings (so far)

| Name | Example | Meaning |
|---|---|---|
| `NODE_ENV` | `development` | Which mode we run in. In `production`, logs are plain JSON and later some safety options switch on. |
| `PORT` | `3001` | The port the API listens on → `http://localhost:3001` |
| `LOG_LEVEL` | `info` | How chatty the logs are. `debug` shows the most; `error` only shows problems. |

## Format

One `NAME=value` per line; `#` starts a comment. No spaces around `=`.
Values are always read as text; [`env.ts`](src/config/env.ts.md) converts them
(for example `"3001"` → the number `3001`).
